# 0041 — A define names its apparatus, and the engine checks it reached the child

Status: Accepted (2026-09-03)

Closes #257. The eighth key of the define (`[world] state` and, in `[define]`, the seventh),
and the fifth time DESIGN.md §12's sentence — *if Define ever needs more than this, that is
movement toward the kill criteria in §18, and we should notice* — is faced on the record.

## Context

The cohorts that measured real targets under the provenance gate made three of them
deterministic by hand: libfaketime through `/etc/ld.so.preload` with `FAKETIME` set,
a generated `sitecustomize.py` on `PYTHONPATH` pinning `time.monotonic` and `os.urandom`,
a `RUSTC` stand-in, `PAPIS_NP=0`. Every one of those lives in a launcher script (`ops/explore.sh`)
or in the define's own `setup`, and the committed toml carries no trace of it —
`spike/cohort2/borg-r3/ops/borg-create.toml` says in a comment that the "apparatus reaches the
operation child from the launcher's environment". A reader of the define, or of the report it produced, cannot tell
what the question was: the same toml explored without the launcher is a different experiment,
and it refuses at the baseline (`baseline_violates_invariant`, naming the path since #199)
rather than saying which device was missing.

The 2026-08-26 reading deferred this because two of the nine devices cannot be expressed as
config at all (a seccomp profile is the container's boundary; a pid pin applied inside the
operation's own command line is not the engine's to see), and because the report side depended
on #320, which has since closed. Counted for this decision (`docs/apparatus.md` lists them):
six of the nine are checkable entries, three are notes — the two above and one line in a
tool's own rc file. The owner ruled on 2026-09-03: a declared key, verified by the
engine, applied by nobody but the launcher.

## Decision

`[define] apparatus` is an array of strings, each `kind:value`, with four kinds:

| entry | what the engine checks before recording |
|---|---|
| `env:NAME` / `env:NAME=VALUE` | `NAME` is in the environment the operation will inherit; with a value, the value is equal |
| `preload:LIB` | Linux: a line of `/etc/ld.so.preload` names a library whose basename starts with `LIB`. Never `LD_PRELOAD`: the engine replaces that variable with its own shim for every child (`main.zig`, the recording pairs), so a library there does not reach the operation — and if `LD_PRELOAD` does name it, the refusal says so. macOS has no global preload file and the engine owns `DYLD_INSERT_LIBRARIES`, so `preload:` is refused there as unsatisfiable |
| `pythonpath:FILE` | some entry of `PYTHONPATH` has `FILE` directly under it. Existence only; the file's content is not judged |
| `note:TEXT` | nothing. Carried, and listed as unchecked |

The check runs **after `setup` and before the initial snapshot**, on every path that runs a
define (`explore`, `preflight`, `replay`): the two cohorts' devices that the engine can see
were generated by `setup` (the sitecustomize, the RUSTC stand-in), so a check before it would
refuse the honest define. A missing entry is a SETUP ERROR (exit 3) naming the entry and what
was looked at. The environment inspected is the engine's own, which the CLI child inherits, plus
the pairs the engine adds; names the engine owns (`LD_PRELOAD`, `DYLD_INSERT_LIBRARIES`,
`TOY_STATE`, `SIDEEYE_*`) are refused at parse time, because declaring them would be declaring
the engine's own doing. Under the MCP server the child's environment is the minimal one plus
`SIDEEYE_MCP_CHILD_ENV`, and that is what the CLI child sees, so a device left off the allowlist
fails here rather than as a silently different run.

The report carries the declaration verbatim in `apparatus` and the `note:` entries again in
`apparatus_unchecked`, both present only when the define declared something (the presence rule
`next_step` and `divergence_syscall` follow), so a report from a define without the key reads
as it always did and a SETUP ERROR raised before the config was read carries no empty array
that would mean "declared nothing". `--apparatus ENTRY` is the flag form, repeatable, and joins
the define-surface flags that are exclusive with `--config` (ADR 0007).

**The saved case does not carry it.** Cases are a closed set of versions with a gate per field
(surface 4); carrying the declaration would be version 5, two refusals and a wording change to
`docs/contract-freeze.md`. A replay without the declared apparatus is not silent: the baseline
does not repeat the recorded bytes and the refusal names the path (#199). That is the safety
net this decision leans on, and the gap it accepts.

## Answering the test `cwd` passed

DESIGN.md §12 said, when `cwd` was added, that the environment was "the nearest sibling and was
deliberately left out: `SIDEEYE_MCP_CHILD_ENV` and the CLI's inheritance already give every
caller a way to set it, so it fails the 'no other way to say it' test". That test is still the
test, and `apparatus` passes it for a different reason than `cwd` did: it is not a way to
**set** the environment. Setting stays where it was — the launcher, `setup`, the allowlist. It is
the only way to **say**, in the artifact the report carries and a reviewer reads, that this
define assumed these devices; the launcher script is not that artifact, and a comment in the
toml is not checked. What the key adds is a claim the engine can hold the run to, which is what
distinguishes it from the free-text `apparatus.txt` that campaign records already keep.

It still says nothing about the target's behaviour, which is the shape §12 refuses.

## Alternatives considered

- **The engine applies the apparatus** (sets `LD_PRELOAD`, writes the sitecustomize). Refused by
  the owner: the engine would be composing the experiment rather than judging it, and the one
  device that matters most (a global preload) is a machine-wide side effect the engine should
  not own.
- **No key**: keep the cohort protocol's three-tier declaration and the launchers. That is the
  state that produced defines which are not the whole question.
- **Free text**: `apparatus = "faketime, sitecustomize"`. Unverifiable, and the campaign records
  already have that in `apparatus.txt`; it did not stop the toml from lying by omission.
- **`preload:` checked against `LD_PRELOAD` too**. The first plan did this. The engine overwrites
  `LD_PRELOAD` for every child, so a library there is a device that does not arrive; checking
  it would make this feature manufacture the silent false pass it exists to remove.
- **Carrying the declaration in the case.** Considered and dropped for the cost above.

## Consequences

- Campaign rule unchanged: a finding is claimed only after it reproduces on the stock tool.
- The checker's environment is the define's business: a checker may drop a device on purpose
  (cohort 3's cargo-r2 unsets `RUSTC`); the check is about the operation's environment only.
- `/etc/ld.so.preload` is global. A library named there rides on every process of the run,
  the engine's `/bin/sh -c` included — the shape that once made every world report
  `child_process_detected` — and on `strace`'s children under the oracle. `docs/apparatus.md`
  says so beside the recipe; the engine only reads the file.
- The acceptance suite cannot write `/etc/ld.so.preload` on the runner: it is one file for the
  whole job, and every other leg would inherit it. The positive observation of a preload
  reaching a child is a host measurement in a container (recorded in the PR), the content
  predicate is a unit test, and CI holds the negative legs.
- `pythonpath:` proves a file exists, not that it is the file the define meant.
