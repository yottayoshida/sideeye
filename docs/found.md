# Found by Sideeye

Every report this project has filed on GitHub is listed here: each one in `spike/upstream-reports.tsv`, and each issue the repository's owner opened on someone else's tracker that names Sideeye in its body and is not in that ledger yet, marked *not in this project's record yet* and listed under *Filed and not in this project's record yet* until it is. A report filed outside GitHub is not here.

Every day the `upstream-watch` job reads every one of those reports and the pull requests in its repository that are linked to it or mention it. When any of that differs from this page on main, it opens one pull request that regenerates the page for all of them, closing the one it opened before; when a report cannot be read, the job fails and opens nothing. An issue its tracker no longer has shows as *Gone*. This page is as current as the last of those pull requests that was merged. GitHub stops a public repository's scheduled jobs after sixty days without activity, and the job stops with them.

*What it is* is the repository's own description and *Issue* the issue's title, both upstream's words made plain text. *Status* gives the tracker's word first and then this project's record from `spike/outcome-funnel.tsv`: *fixed upstream, re-measured* means this project ran Sideeye again against the fix; *acknowledged*, *fixed upstream*, and the reason a report rests where it does — *awaiting* a reply, *declined*, still *discussing*, *withdrawn*. The two are kept apart because a tracker closing a report as completed is not a fix: qpdf's was closed as completed and the fix declined. *Sideeye* is the version the filing campaign ran (`spike/campaign-versions.tsv`) — a release, or main after one. *Found* is the date of the campaign that filed the report, or the day the issue was opened for one not recorded yet. Comment counts and last activity are not here; `spike/upstream-report-status.sh` reads those. Counterexamples Sideeye found and nobody filed are not here either; `docs/outcome-funnel.md` counts those. The counts and the tables below are generated; these paragraphs are written by hand.

The first table is a list of counterexamples Sideeye found, not a badge: nothing on it says a tool is safe, and a tool missing from it was not shown to be ([DESIGN.md](../DESIGN.md) §15 rules badges out). The table under *Filed while working with Sideeye, without a Sideeye verdict*, when there is one, lists the reports this project filed whose finding was not a Sideeye verdict — a plain script, a run by hand, analysis after the run — and gives them no *Sideeye* version; `docs/outcome-funnel.md` says how the ledger marks them (#825).
