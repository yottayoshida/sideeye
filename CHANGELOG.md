# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Until v1.0, any of the five frozen-at-1.0 surfaces — the Define contract, report schema, exit codes, replay compatibility, the MCP surface (`docs/contract-freeze.md`) — may change in any release.

## [Unreleased]

### Fixed

- **The guarded-descriptor family is recorded, and the shim's coverage is now measured against the oracle's rather than against a list** (#299, part). macOS interposes 52 functions and nothing said what that set should be compared to: `check-macos-coverage.py` holds `libsystem_kernel`'s exports against a curated ten and says so itself, while the Linux side has promised since #256 that "every syscall the oracle classifies is either interposed or explained" and stated in the same paragraph that macOS could not keep it. ADR 0031 gave macOS the oracle that promise needs. Comparing the two observers found a family: `guarded_open_np`, `guarded_open_dprotected_np`, `guarded_close_np`, `guarded_write_np`, `guarded_pwrite_np` and `guarded_writev_np` are exported by libSystem, printable by `fs_usage`, imported non-weak by `/usr/lib/libsqlite3.dylib`, and were interposed by nothing — so on the default path, where the shim is the only observer a run without root gets, a target writing through them produced **zero recorded operations** and any other recorded mutation carried the run to PASS. That is #333's shape one family over. All six are interposed now; `explore` over a toy that calls them reports crash points where it previously reported `state_changed_without_ops` — six on a volume that supports a data protection class and four on one that does not, since `guarded_open_dprotected_np` returns `ENOTSUP` there. The toy reports which of the two it exercised and the acceptance leg takes the expected count from that line, rather than from a constant that was right on one machine. `spike/check-fsusage-coverage.py` is the new check. It derives the spelling difference between what `fs_usage` prints and what libc exports (`open_dprotected` against `open_dprotected_np`) from the syscall table `fs_usage` carries in its own binary, cross-referenced against the SDK header — **not from a table anyone wrote down**: a hand-written spelling table was tried first and review turned two real uninterposed writes green by adding two rows to it, which is the shape `check-shim-coverage.py` refuses on Linux. Its anchors come from the `OpClass` enum rather than a list of names, because name anchors left 20 of 26 classifier rows deletable with the check still green. Three classified calls this `fs_usage` cannot print are recorded as such and the check refuses if a later build prints one. **This does not close #299**: the ticket asks for three measurements before any design and this answers half of one — the size of the surface, not the runtime cost of wrapping it, and neither the reachability of `dlsym`-resolved calls nor a static `svc` scan's false-positive rate. The generated-interposer proposal stays unbuilt.

- **`--config` is read under a deadline as well as a ceiling, so a pipe cannot stall the run.** Three inputs used to produce no exit code at all: a FIFO with no writer (the open waited for a peer), a pipe whose writer had opened and sent nothing (the read waited for bytes), and `/dev/zero` (a read with no ceiling — `readFileAlloc` passed `maxInt(usize)`). Measured on macOS, the first and the third ran past eight seconds; the second was measured against the rejected design and is recorded in `spike/config-read-bounded.txt`. The config read now opens non-blocking and keeps asking while a peer might still arrive, refusing after two seconds; the byte ceiling is 1 MiB, against a largest committed config of 4.5 KiB. **A config that arrives late is still read** — a writer that opens and writes a second in is picked up and parsed, which is the behaviour a blocking open gave and which the first draft of this change broke. `--config /dev/null` and an empty **regular** file are unchanged and still answer immediately: the retry asks whether the descriptor is a FIFO, not whether the read came back empty, because those two mean opposite things.

  **Three inputs answer differently than before, and all three are the price of the bound.** A config over 1 MiB is refused where it used to be read (exit 2 becomes exit 3). A producer slower than two seconds — including a config that streams across that window — is refused with the partial read discarded; the deadline is absolute, not idle-based. And a pipe whose writer opened, wrote nothing and closed is *empty*, but reads exactly as one whose writer has not arrived — POSIX gives no way to tell those apart — so it waits out the deadline and is reported unreadable rather than empty, where before it was reported as a config missing `[world] state`. **One usage is outside the deadline and stays that way**: on macOS `--config /dev/stdin` (and `/dev/fd/N`) is handed a duplicate of an existing description, so the flag never reaches the pipe and a stalled writer still stalls the run — unchanged from before, and the opposite of Linux, where the same path gets its own description and is bounded. Every refusal *message* is one that already existed, and no verdict or `unknown_reason` moves.

- **The freeze audit says which check pins which clause, or that nothing does** (#369, ADR 0028). Rung 3 of the surface-drift measurement printed its residue as five paragraphs ending "these are held by review and by `spike/acceptance.sh`" — true of the set, and useless for any one clause: a reader could not tell whether a check watched it or nobody did. `spike/freeze-audit/clause-checks.tsv` now answers per clause, and rung 3 prints only what is unpinned plus the leftover half of what is pinned in part, so a clause covered in full disappears from the output and the list shrinks as checks are written. Today it holds 26 clauses: 11 pinned, 6 partial, 9 unpinned. `held` has three values rather than two, because two would make every partially covered clause read as covered — the misreading the issue was filed about — and the `gap` column carries what a future check would have to add. The `by` column names a suite and a heading rather than a check id (two ids are duplicated in `acceptance.sh`, and surface 5 lives in `spike/mcp-acceptance.sh` entirely, so reading one suite would have called four covered clauses unheld); rung 3 fails when a named heading is gone — loud to whoever runs the sweep, which is the only reader it has: no workflow invokes `surface-drift.sh`, so a renamed heading still merges green and the row stays stale until the next sweep. **No new check is added** — the issue rules that out, since a change that polices checks cannot also supply them without making a mutation unattributable, so the nine unpinned rows are the output rather than a shortfall. What stays unmeasured, and says so, is whether the enumeration is complete: a clause is one independently checkable assertion, which matches no boundary in the declaration. When the file holds no unpinned and no partial row, the run says the rung can be retired.
- **`sideeye mcp` finds its shim the way the rest of the product does** (#389). `README.md` has always said Sideeye "looks for the shim beside itself before `../lib`", and the CLI has always done that — but the MCP server demanded `SIDEEYE_MCP_SHIM` and refused every `tools/call` without it, in the same file that defines the helper discovery needs. A Homebrew install resolves on the second candidate with nothing set, measured. **`SIDEEYE_MCP_SHIM` remains, as an override**; what changes is that its absence is no longer a refusal, and the refusal that does remain — neither candidate present — names both paths it looked at. The search order **and the probe** live in one place now: sharing only the candidate list left the two ends free to disagree, and they did. **The search trusts the install directory** — whoever can write `bin/` or `../lib` chooses the injected library, and a symlink there is followed. That is how the CLI has resolved the shim since #78, measured on the shipped 1.0.0, so it is the product's posture rather than something this adds; what this adds is that the server shares it. `README.md`'s table and ADR 0010 now say so, and #423 carries the product-wide fix.

- **The README's MCP section carries a first call that works, and CI runs it** (#389). Driving `sideeye mcp` from that page alone, on the shipped v1.0.0, was refused four times, and three of the four were recoverable only by reading `src/mcp.zig`: `_meta` is per-request and mandatory under namespaced keys, there is no `initialize`, and every `tools/call` needed a shim path — a variable named in no operating document, while the section around it explained two others in depth and so read as complete. Measured across all six the server reads: two are in `README.md` and `docs/ci-quickstart.md`, one more is in `DESIGN.md`, and **three are in decision records only**. The section now carries the whole table, the schema date, and two runnable blocks — an environment block and the exchange — and `spike/check-readme-mcp-call.sh` extracts and runs exactly those blocks **from a cleared environment** on every pull request and every push to main, on Linux and macOS. The clearing is the point: `spike/mcp-acceptance.sh` exports the server's variables before any of its fourteen legs run, which is why none of them could observe what a caller starting from nothing must supply. `spike/check-mcp-env.py` holds the table to the code in both directions, walking **`getenv` call sites** rather than matching variable names — the server also reads `PATH` and one variable whose name is a runtime value, neither of which a name-shaped scan can report. **Both `_meta` refusals now name the key the server actually looks up**; they used to name a spelling it does not accept, so a caller who pasted the identifier out of the refusal got the identical refusal back. The one item this does not close by machine is `initialize` answering `-32601`, which is the schema showing through and is answered by naming the schema date.

- **The apparatus record a sweep writes is now read** (#348). `sweep.sh` writes each generation's `apparatus.txt` — the engine banner, the engine and shim digests, the `head:` the sweep ran on, and the image ids — and `count.py` opened it zero times, so a truncated record or none at all passed every rate check that exists. `count.py check` refuses a complete generation whose record is missing, carries other than two digest lines, has no `head:` resolved to forty hex, or fails to name every image its manifest uses — a set difference, not a count, so a record naming images the manifest never used still refuses if it is missing one the manifest did. The predicates follow what truncation reaches first (images, then `head:`, then the digests), and two of them cover the only failures the writer does not guard: nothing there checks the rc of `git rev-parse HEAD`, whose failure writes `head: ` with no value and continues, or the result of `docker images | grep`, whose empty output writes no image lines. **What this establishes is that the record is intact, not which images the trials ran under** — the sweep lists every `sideeye-ur-*` on the host rather than the ones it used, so the record's image set is a superset of the run's, and the page says so. The banner line is deliberately unchecked: truncation cannot remove it alone. The issue's second half — a flagged trial reaching the rated set is checked in only one place — needed nothing here: that guard was deleted earlier as true by construction, its one reachable input is now covered by the duplicate-id check over all corpus rows rather than the three carrying flags, and what a flagged row reaches is held by the attribution checks against every published aggregate. Measurement tooling only — no engine behaviour changes, no frozen surface moves, and the published figures are unchanged.

- **An ADR's Status says whether its decision shipped, and CI holds it there** (#360). Five ADRs sat at `Proposed` with their implementing PRs long merged, because the convention asked for something one pull request cannot do: the ADR file arrives inside the PR whose work it decides, so flipping it to `Accepted` is always a second commit. Measured over the whole history, that second commit happened for twenty of twenty-five born-`Proposed` ADRs — the five that missed it are all from the three dense release days of 2026-08-25..27, so the rule was working until output bunched up. The default is inverted now: an ADR is written `Accepted` with provenance (`Accepted (YYYY-MM-DD)` at minimum, the merge sha once one exists), and `spike/check-adr-status.sh` refuses anything else on pull requests and on `main`. **Pre-registration keeps its `Proposed`**: a campaign Seal A declares its ADR before the campaign runs, so `Proposed (design-first: …)` passes and a bare `Proposed` does not — the marker is a claim rather than a proof, in the same way `Filed-under:` is on an issue. The check reads the first word of the Status line only, which is what keeps it off two correct files (`0002` carries `proposed` inside a parenthetical, `0030` discusses a proposal in its body), and it fails on a missing Status line, on a directory it found empty, and on a walk that covered fewer files than the directory holds. Nothing about a release changes; no frozen surface moves.
- **A change the account does not explain refuses instead of passing** (#405, detection half; ADR 0032). The zero-ops detector asks whether the state moved while *nothing* was counted, so it goes silent as soon as one operation is recorded — and a target that writes one file through libc, then forks with `syscall(SYS_fork)` and has the child write a second through raw syscalls, reached **PASS, exit 0** with the child's file in the judged directory. Measured on the shipped 1.0.0 and again on `main`. The general form of that check is per path: every difference between the initial and final snapshots must be named by some recorded operation, and the run refuses (`state_changed_unaccounted`) naming the paths that are not. `open` counts as naming a path here even though it is not a mutation — excluding it makes the zero-ops form stricter and this one wrong — and every record counts, not only the subject's, because *who* changed the state is a different detector's question. **The direction is one-way**: an unnamed path is evidence the account is incomplete, while every path being named is not evidence it is complete, and the code says so where a future caller will read it. **A directory renamed in from outside the judged root carries its children**, because that source subtree was never snapshotted and nothing this run holds can recover what arrived with the move — so those paths are attributed to the rename, and their count is reported in a new field, `paths_attributed_to_rename`, on every report. "From outside" is required: a rename inside the judged root, or one moving a subtree out, has its source in the initial snapshot and is reconciled path by path like anything else. `README.md` names this one exception in the sentence that makes the promise, rather than leaving it to an ADR. **A path the shim recorded through an interior symlink names what the snapshot holds**: the shim normalises lexically and records `cur/f` while the snapshot, which never follows a link, holds the difference at `v1/f`, so the join substitutes link prefixes from the snapshots' own record of targets — never from the live tree, which is no longer the tree the operation crossed. Both spellings are compared, because a record can name a link (`unlink("cur")`, difference at `cur`) or name through it (`unlink("cur/f")`, difference at `v1/f`), and those are different objects. Where the substitution cannot be sure it declines and the run refuses: a link whose target moved during the run, and a path two links both match. Runs with an oracle are unaffected in reason: `oracle_missed_operation` names the syscall, which is strictly more, and it is asked first. **`toy-mixed` — the target written to defeat the structural detectors — now refuses without an oracle where it used to FAIL**, and the FAIL was the worse answer: its crash points came from an operation list that omitted the write the counterexample was about.
- **The `unknown_reason` closed set gains a member after the tag, which the freeze declared breaking.** `state_changed_unaccounted` takes it from 32 to 33. Every existing member was checked against the code rather than its name and none could carry the refusal without saying something false: `state_changed_without_ops` spells zero recorded operations and this run records one; `completeness_not_verified` reads no evidence from the run at all and is structurally unreachable for the `--allow-unverified` reproduction; `oracle_missed_operation` is the oracle's finding and this detector runs without one; `boundary_without_oracle` needs a boundary the shim recorded, which is exactly what is absent. `docs/contract-freeze.md` keeps its original paragraph and carries an amendment saying the promise was not kept; `surface-changes.tsv` gains a new `legality` value, `freeze-broken`, which is deliberately not a synonym for `declaration-amended` — amending the declaration is what happens after breaking it — and the row itself lands with `DECLARATION_PIN` in the follow-up audit commit, the way `2e6f85d` recorded the members before it. **The rule for 1.x is unchanged**: the next member needs its own ruling, not this precedent.
- **A case path that is not a regular file is refused instead of stalling the run** (#400). `sideeye replay <case>` did not return when the case path named a FIFO with no writer: the open waits for a writer that never arrives, and nothing above it has a timeout — `--world-timeout` bounds a world's operation, while this is the parent reading a file before exploration starts. The MCP server reaches the same read through its replay tool, where a stalled run is indistinguishable from a long exploration until someone looks. Measured on macOS against a real FIFO: the open had not returned when the measurement stopped it at five seconds (#400 reports fifteen). The open now passes `O_NONBLOCK`, **and** the descriptor is classified before a byte is read. Both halves are needed: a FIFO with no writer answers end-of-file rather than an error, so the flag by itself turns "could not be read" into an empty case file, which then fails to parse — the run exits 3 either way, but blames the JSON for a file it never read. The demand for a regular file is made at the case read only, and **the flag travels with it**: passing `O_NONBLOCK` to a read that will not be classified turns a pipe whose writer has not written yet into a refusal, which was measured to break `{ sleep 1; cat sideeye.toml; } | sideeye explore --config /dev/stdin` — so `--config`, the fs_usage capture and the falsify gate's output keep the blocking open they had, and process substitution still works. The same reader shape is fixed in four more places — the capture tail, the capture observation, the snapshot's whole-file read, and the MCP server's read of its report. What that buys differs by call site and is not uniform: for the snapshot walk a `readdir` race that used to hang now refuses, for the MCP server a planted FIFO no longer stalls a request that has no timeout around it, and for the trace read the answer is the same `no_shim_marker` it always was — that reader folds every failure except an oversized file into an empty trace, so what changed there is that a hang became a fast wrong answer, not that the wrong answer went away. `openRootDir` is deliberately unchanged, since `O_DIRECTORY` already refuses a FIFO with ENOTDIR. **Verdicts, exit codes and every refusal name are unchanged; two refusal messages are not** — the case-read message now lists "not a regular file" among its causes, and a case path that is a pipe or a device gets that refusal where it used to reach the JSON parser and be told the file was not a case.
- **The `processes` account stops answering a question nothing looked at** (#405, report half). The field defaulted to the string `"single process"` and three sites overwrote it wholesale, so every path that reached a report without evidence published an assertion about the target. Measured on the shipped build: a target that forks with `syscall(SYS_fork)` and has the child write into the judged directory reaches PASS, exit 0, `processes: single process`, with the child's file still there — the shim interposes libc `fork`/`spawn`/`thread` and a raw syscall is invisible to it, so nothing that could have seen the boundary had looked. Two further paths were found while fixing it and are closed by the same change: a run refused before its trace was read (an operation exiting the wrong status, say) published the same assertion with no account of any kind, and a run whose shim recorded a boundary while `strace` saw no other process published it while the two witnesses disagreed — reproduced with a `vfork` failed by `RLIMIT_NPROC` (`spike/toys/toy_vfork_fail.c`; PASS, exit 0, two crash points, unchanged by the fix). The account is now rendered from evidence: what each witness looked at, what it structurally cannot see, and where they disagree, both sides. `fs_usage`'s silence is not the assertion either, because its exclusion list drops whole processes by name (ADR 0031 §2a). **`strace` seeing no other process still reads `single process`**, which is what the README's example report and the cohort rows record. **The verdict, the exit code and the crash-point count are unchanged on every path** — this is what a run says about itself, not what it decides. Rendering also closes a disclosure loss the old shape carried: the world-only site overwrote the whole sentence and dropped the self-exec image disclosure (#123) the recording had set, which its acceptance check could not see. The field had no unit test at all; it now has a table over the reachable evidence states.

### Added

- **`paths_attributed_to_rename`**, an integer on every report (#405, ADR 0032): how many differences were attributed wholesale to a directory a recorded `rename` moved in from outside the judged tree, rather than named individually. Zero — the common case — says the run has no such gap, which is why it is a number in every report rather than a sentence that appears only sometimes. Additive under the allowance surface 2 of `docs/contract-freeze.md` keeps open; a consumer that reads the schema as "these fields and no others" is reading the one thing 1.x does not promise.

- The freeze-audit gate reports a moved declaration as **staleness** rather than failing on it (#371). It exited 1 — the malformation code — and told whoever saw the red to "re-read the surfaces, then update DECLARATION_PIN in the same commit", which only a sweep can honestly do: a pin asserts that somebody read the five surfaces against that revision, so an author whose change moved the declaration would have been putting their name on a reading they had not taken. Both ages now report together at the end and exit 3, the code surface drift already used for the audit noticing its own age, and both messages say what a sweep does and, separately, that an author who moved a surface has nothing to do here. Exiting 1 also stopped every leg behind it: `main` carried an unrecorded frozen-surface movement (`config_keys` gained `cwd`, #395) from 2026-08-29 with nothing reporting it, because the leg that would have was never reached. Continuing is safe because no leg between reads the declaration — it is read in leg 1 and reported at the end. ADR 0028's paragraph describing the old split is superseded in part, and `docs/freeze-audit.md` now records the ruling that the ledger row and the pin stay coupled, with the decoupled arrangement written down as the shape to move to if that directory ever stops being sweep-owned.
- The acceptance leg for a case recorded under an older trace contract asserts what its success line claims (#370). It printed "refuses as a contract mismatch, never a verdict" behind two conditions — exit 2 and a message substring — so neither the refusal's reason nor the absence of a verdict was checked. The substring is not specific to the subject either: two sites emit `different trace contract`, one for a saved case under an older contract and one for a shim and engine speaking different trace versions in one run, and `docs/contract-freeze.md` surface 4 states that the second "is a different refusal entirely … nothing to do with saved cases". The reason name is what separates them. The leg now asserts exit 2, `^UNKNOWN  case_no_longer_applies$` matched whole, exactly one `UNKNOWN` headline, no `PASS`/`FAIL` line, and the message. Three mutations were built and run one at a time — the reason changed to `contract_version_mismatch` (which the old predicate accepted, message unchanged), a `PASS` line printed beside the refusal, and the message reworded — and each dies to a different clause. The headline count is defensive rather than demonstrated: `unknown()` is `noreturn` and the sole writer of that line, so no reachable mutation of this path produces a second one.
- `spike/check-adr-numbering.sh`, wired into CI: `docs/adr/` holds nothing but ADR files,
  every name is `NNNN-slug.md`, and the four digits are unique (#373). Numbering is
  highest-plus-one and reserves nothing — on 2026-08-27 two sessions each wrote an
  `0028-*.md`, the slugs differed so the filenames differed, and git merged both without a
  conflict; the only thing that noticed was the two sessions telling each other. **The
  population assertion is the load-bearing half**: the first draft scanned
  `-type f -name '*.md'` and called that "every filename", so a symlink, a directory named
  `0031-x.md`, an uppercase `.MD` and a plain `notes` were each invisible — four ways to
  collide that reported `every number unique`, all four measured in review. Two
  independent counts stand behind the walk for the same reason: comparing a walked count
  against a file count taken from the same `find` expression let a narrowing of `-name`
  walk 29 of 31 and report `ok`. Contiguity is deliberately unchecked — renumbering the
  second 0028 to 0029 leaves 0028 a gap until the other side lands, which is the correct
  state during exactly the window the check matters. It **reports** a collision rather than
  preventing one: no status check is required here, so a branch cut from a `main` that
  already holds the number goes red on its PR, but two branches from the same base can each
  carry a unique number and both merge, surfacing on the post-merge run. A `--selftest` leg
  runs first in CI and proves the check can go red on every run, because the uniqueness
  pass is a pipeline with no `set -e` behind it and breaking its `sed` reports a directory
  holding a real duplicate as unique.
- `--oracle-fs-usage`: on macOS the recording run can now be compared against
  `fs_usage`, giving `oracle_verified` the same meaning it has on Linux instead of
  leaving every PASS on `--allow-unverified` (#286, ADR 0031). Needs root, so sudo
  must already hold credentials — the run refuses rather than prompting. Narrower
  than the strace oracle, and each narrowing refuses rather than agrees: a rename is
  checked at its old path only (fs_usage prints no destination); a process boundary
  is not tolerated, because fs_usage excludes some processes by name; a `chdir` by the
  subject leaves relative operands unplaceable; a state directory deep enough to be
  cut by the display width is refused before the run. Two things it cannot see and
  says so: a process leaving the containment group, and a neighbour's descriptor into
  the state directory opened before the capture began. Runs that do not pass the flag
  are unchanged.

### Fixed

- **The record of what this project filed upstream is no longer a literal nobody is required to edit** (#297). `spike/upstream-report-status.sh` measured six reports because six were written into it by hand, and a report filed without editing that literal was invisible: the table looked whole, every row read fine, and the script exited 0 — six of seven prints exactly like six of six, and the cohort-4 close depended on remembering to add himalaya by hand (PR #253). The filings now live in `spike/upstream-reports.tsv`, and each one also carries an `<!-- upstream-report: owner/repo#N -->` marker on its row in `docs/target-classes.md`. `spike/check-upstream-ledger.sh` holds the two to each other in its own CI job — both directions, the row the marker sits on, and the ledger's own shape (exactly four tab-separated fields, a status inside its vocabulary, no duplicate identifier), each of which was a way to lose a row in silence — and `upstream-report-status.sh` takes its standing subset from that checker (`--standing`, which runs the whole check first) rather than selecting rows again, so the rules that decide which rows count have one implementation instead of two obliged to stay in step — restating them had already drifted inside a single review round, with the two spellings of "comment" disagreeing about an indented line and the table printing `read 7 of 7` over six standing reports. The status script itself is not run by CI, since it reaches the network; its own selftest is what holds it, and that selftest gained legs for an empty ledger and a misspelled status, neither of which could exist while the list was source code. The reporting procedure in `spike/cohort4/PROTOCOL.md` now names the writes a filing needs. **What the pair cannot see is a filing written into neither record — and prose is not one of the records**: a row naming a report in its text and carrying no marker is invisible here, which is the recorded accident with only its prose half done. The closing line says that instead of implying otherwise: deriving the set from a tracker was measured and rejected, because `--author` returns the issues of whoever is authenticated rather than the project's, a search exposes no completeness signal to read, and the exclusion list such a design needs becomes a second place to forget something silently. `alecthomas/devtodo#9` — filed and withdrawn the same day — sits in the ledger as `withdrawn`, which is the first time that filing has been machine-readable anywhere rather than a URL inside a sentence.

- **The shipped build values are held by tests, not by a sentence** (#365). Four values reach a release — the engine's two trace-read ceilings, its ancestor-probe flag, and the shim's numbering-gap flag — and CI's sha comparisons covered only the case of a build FLAG leaking into a shipped artifact. An edit to the literal in build.zig lands in both arms of such a comparison and leaves it green, so the #270 and #324 entries below promised more than "asserted in CI" delivered. Unit tests now assert each shipped value against the shipped options module — the same module object a released binary is built with, rather than a second one built from the same literal, which nothing held together — a declaration count is pinned per options module (three in the engine's, one in the shim's) so a further option cannot arrive unchecked, and `zig build` asserts at configure time that each shipped artifact is built with the module those tests read — without that last part, repointing an artifact's import was a single edit that left the whole suite green and shipped the broken value anyway. Nothing a release does changes; the assertions run in `zig build` and `zig build test`. Worth stating precisely, because the first draft of this work repeated the issue's overclaim: a LOUD edit such as a 64-byte ceiling was already caught by acceptance, where the legs that drive the shipped binary refuse on a trace that size (four apparatus binaries are driven by their own names, so this is most of the suite rather than all of it), and that half is read off the suite rather than run. What nothing caught was a quiet one — measured at 128 MiB, where `zig build test` went red while the sha step stayed green on the same tree.
- **A `SETUP_ERROR` can no longer leave the UNKNOWN-rate denominator unremarked** (#347). `docs/unknown-rate.md` has always stated the rule in two halves — an apparatus failure is fixed and the trial re-run, and only "if unfixable, the row is published as excluded, with the reason" — but `count.py` enforced the exception and never asked about the default. Any `SETUP_ERROR` was dropped from the rated set, the generation could be marked complete, and the rate published over what remained, reading exactly like a sweep in which every trial was measured. The judgement now has to be written down before it counts: `spike/unknown-rate/exclusions.tsv` carries one row per waived trial, `count.py check` refuses a complete generation carrying a `SETUP_ERROR` the ledger does not name — and, in the other direction, a waiver whose trial is no longer a `SETUP_ERROR`, which is what a waiver becomes once the apparatus it excused is repaired. The waived reason is published in the excluded row's own cell. The reason is a person's sentence in a committed file rather than the report's `message`: the engine records what failed, never whether anyone tried to fix it, and the same page states that `count.py` reads only machine fields. ### Added

- Case storage and `sideeye replay` (ADR 0009). A FAIL saves its counterexample to `<work>/cases/NNNNNN.json` — the resolved define, the crash point, and a landing context (operation count, a hash of the class sequence up to the crash point, the classes and paths around it) — and prints the ready-to-paste `sideeye replay` line in text and JSON. - The L1 success marker (ADR 0008): `marker` in `sideeye.toml`, or `--marker`. In worlds where the operation's own success claim reached stdout before the kill, the post-success invariant is enforced against the whole post snapshot — shared files must hold the new content, history files must have grown, created files must exist, deleted files must stay gone (`not_durable`). A marker the clean recording run cannot produce refuses as UNKNOWN `marker_never_observed` instead of leaving every L1 obligation silently vacuous; a crash world killed before the marker is simply a world where the conditional does not apply, and is still judged by L0 and the checker. The parser is a hand-written strict subset that refuses everything outside the contract with the offending line named: unknown sections and keys, bare values, duplicates, empty values, escape sequences. Keys join the schema only once the engine enforces them (`marker` refuses until L1 lands). The file owns the define surface only — operational flags (`--shim`, `--oracle`, `--work`, `--json`, `--allow-unverified`) stay flags and combine with it; the define-surface flags are mutually exclusive with it, never merged. Relative paths resolve against the toml's own directory; command argv[0] resolves only when it names a place (`./check.sh`), never a program name. Command strings keep the flags' split-on-spaces rule, now written down.

- A refusal names the operation it refused on. `oracle_missed_operation` and `oracle_saw_phantom` now carry the 1-based divergence index, the raw strace line the oracle holds at that position, and what the shim's account holds there — or that either account simply ends — in the text report and the JSON `message` identically. Previously the comparison computed the divergence index and threw it away on the way to a one-line refusal, leaving the reader to decode `trace-record.bin` by hand; two dogfood sessions paid that cost in full. No schema change, no trace-contract change (v7 stays). On allocation failure the bare refusal survives without the naming — the refusal is the point, the naming is the courtesy.

- The shim observes `remove(3)` (trace contract v7). libc implements remove as unlink — then rmdir on the directory errno — *internally*, behind the PLT, so a target that removes state through it was invisible to the shim while the oracle saw every syscall: on Linux such a run refused honestly (`oracle_missed_operation`), but on macOS — which has no oracle — a mixed-visibility target keeps `mutation_count != 0` and leaves `state_changed_without_ops` silent, which is a PASS hole, not an ergonomic gap. The wrapper reimplements the documented two-step through the shim's own recorded unlink/rmdir wrappers, so every attempt is recorded before it runs and the account matches strace attempt for attempt: a failed remove of a never-created path is an address on both sides, and a directory shows glibc's failed unlink probe before the rmdir lands (Apple's BSD libc falls through on `EPERM` instead of `EISDIR`; each platform keeps its own libc's behaviour, warts included). Found by timewarrior, whose AtomicFile cleanup removes every registered temp name at exit, created or not. **Contract v7**: a target that removes state via remove gains crash-point addresses a v6 trace does not have — the same class of meaning change that bumped v4 and v5.

- `spike/dogfood-timew.sh`: the fifth real target, and the first counterexample on a real target that is not a precision artifact. One `timew track` commits three files by consecutive renames — month data, then `undo.data`, then `tags.data` — so every file is individually atomic and L0 alone passes 20/20 worlds; the bug is not in any file but between them. A checker stating only timewarrior's documented undo contract (undo removes exactly the interval timew's own export names as most recent) fails 2 of 20 worlds. Killed between the first and second rename, `timew undo` reports success and deletes an interval committed long before the crash, keeping the one whose commit crashed. Killed before the third, `timew undo` exits 255 ("Trying to decrement non-existent tag") and stays unusable until `tags.data` is repaired by hand — it undoes nothing, atomically, which is the good half. Both replayed end-to-end from the reproduce line. The falsification probe passes bare: `timew export` rejects a corrupted data file loudly (exit 255), the opposite of todoman's lenient reader.

- The oracle decides scope by resolving each syscall's real path arguments instead of scanning the whole line for a state-directory string (ADR 0006, trace contract v6). A relative path resolves against its `dirfd` annotation or the tracked working directory (updated from the subject's own `chdir`/`fchdir`), and one that cannot be placed is refused rather than dropped — closing a fail-open where a target that changed directory and spelled its paths relative slipped past the scope test entirely. The same change removes the matching false positive: a state-directory string sitting in a write buffer no longer scopes an fd write in. Two-path operations are in scope when either endpoint is inside the state directory, on both the oracle and the shim (which had judged only the first path, dropping an `outside → state` rename). `link`/`linkat` are now first-class kill points (`OpClass.link`); `linkat(AT_EMPTY_PATH)` and `clone(CLONE_FS)` are refused, and the oracle now honours the alternate state-directory spelling. Measured: git commit reaches account agreement (33 operations, 34 worlds) and a full verdict for the first time — the FAIL it reports is `COMMIT_EDITMSG`, git's editor scratch file, which `git fsck` accepts in every crash world, so git's real integrity is intact and the complaint is an L0 precision limit on a non-durable file. taskwarrior (PASS 12/12) and omamori (PASS 143/143) are unchanged. **Contract v6**: a v5 shim under a v6 engine refuses, because it records no link where a link happened.

- The shim observes stdio streams at flush granularity (ADR 0005, trace contract v5): a write-capable `fopen`/`fopen64` is an `.open`, a flush with pending bytes is a `.write` — at `fflush`/`fflush_unlocked`, at `fclose`, at `freopen`'s [write, close, open] triple, and at the seek family (`fseek`/`fseeko`/`rewind`/`fsetpos`), because libc flushes a dirty stream as a side effect of repositioning it (measured as the only thing standing between taskwarrior and a verdict). Recording happens before the call, so a kill lands before the flush and the crash world loses the unflushed buffer — what a real crash loses. What bypasses the flush path (a large `fwrite` going direct, overflow flushes inside `fprintf`, `fflush(NULL)`, `freopen(NULL, …)`'s reopen, exit-time cleanup of never-closed streams) stays unrecorded and, under an oracle, refuses as `oracle_missed_operation` exactly as before — the unjudgeable class just became much smaller. On macOS (no oracle) the same residue falls inside `--allow-unverified`'s already-declared weaker claim, while stdio visibility goes from zero to everything inside the boundary. Measured on the real targets that motivated #30: taskwarrior reaches **PASS 12/12 worlds** (and passes its own `task list` as an L2 checker in every crash world, after the falsification probe rejected a corrupted state); git's `COMMIT_EDITMSG` no longer splits the accounts and its run now stops one wall later (#31, relative-path oracle scope); omamori is unchanged at PASS 143/143. **Contract v5**: on Linux every affected run was UNKNOWN under v4, but a macOS `--allow-unverified` verdict over a stdio-mixed target could carry a reproduce line whose `k` counts different operations under v5.

- L0 carries a second per-file form, chosen from the snapshots alone: a file whose post-operation content strictly extends its non-empty pre-operation content — the shape of logs, journals and audit chains, whose appended bytes may legitimately differ between runs — is judged by **history preservation** (ADR 0004): after the crash the file must still begin with everything it held before the operation, with a new violation (`rewritten`) when it does not. The appended tail is deliberately not judged; whether a torn tail is acceptable is the target's recovery semantics and belongs to an L2 checker. Every report says which files were judged by which form (a new `l0` note in text and JSON — an addition to the experimental report schema, not a trace-contract change; the contract stays v4), and `not tested` grows "appended tails" whenever the form is in play. The relaxation is exactly as wide as the shape: a non-reproducible *rewrite* still ends in `UNKNOWN baseline_violates_invariant`, pinned by its own acceptance case.
- `spike/dogfood-omamori.sh`: the first real target's exploration, reproducible. Measured with it: the run that was structurally UNKNOWN in v0.2.0 now reaches **PASS 143/143** with `audit.jsonl` named under the history form — and with `--check "omamori audit verify"`, the target's own verifier judges every crash world, including the ~130 that hold a torn audit line (it skips the torn tail by design and accepts), after the falsification probe confirmed it rejects a corrupted state.

### Changed

- Crash-point addressing and the completeness comparison now cover **operations that can change state** (ADR 0003, trace contract v4). A write-incapable open — access mode `O_RDONLY` with neither `O_CREAT` nor `O_TRUNC` — mutates nothing, so the world killed immediately before it is byte-identical to the world killed at the next address; it is no longer observed, on either side of the comparison, under one predicate (`O_RDONLY|O_CREAT` stays addressable — creation can change the tree — though a target whose *only* state change is creating files via open is still refused by `state_changed_without_ops`, a pre-existing and deliberate strictness of that detector). `close` leaves the comparison but stays in the trace: the oracle sees descriptors the shim never saw born, and pairing closes across the views has no honest fixpoint. The oracle-side predicate is fail-closed — numeric or unparseable flags are counted as before, so a parse failure ends in UNKNOWN, never PASS. **`SIDEEYE_KILL_AT=k` counts state-changing operations from v4 on**: a `reproduce` line printed by v0.2.0 may name a different operation under a v4 shim, and a v3 shim under a v4 engine refuses loudly as `contract_version_mismatch`.
- Measured on the target that motivated the change: the two accounts now agree on 142 operations (previously `oracle_missed_operation` on a rustix-issued raw read-only open), all 143 worlds explore with every kill landing, and the verdict is `UNKNOWN baseline_violates_invariant` — correct, because omamori's audit line carries a timestamp and an HMAC chain, so the operation is not byte-reproducible and nothing found in a crash world could be attributed to crashing. The next wall is operation non-determinism versus L0's byte comparison, filed as its own issue.

## [0.2.0] - 2026-08-11

Process boundaries, judged by what the other processes did. This release was not on the roadmap: v0.2 was promised as the full Define contract (`sideeye.toml`, L1 markers, case storage and `replay`), and that scope moves to v0.3 unchanged. What forced the queue-jump was pointing v0.1.0 at its first real target — the run ended at a categorical refusal (`child_process_detected`) for a shape every shim, wrapper and launcher shares, and one of the fixes below removes a v0.1.0 defect that killed the very targets it observed.

### Added

- Process boundaries are now judged by what the other processes did, not by their existence. A target that forks or spawns helpers — the shim/wrapper/launcher shape that ended the first real-world run — is explorable when an oracle is present and no process other than the subject touched the state directory. The rule and the numbering are the same condition: a child that stays out of the state directory consumes no crash-point addresses (ADR 0002). Refusals that remain, each with its own detector: a child that touches the state directory (`child_touched_state_dir`, caught independently by the shim for children that load it and by the oracle for children that do not), any boundary without an oracle (`boundary_without_oracle` — the shim only sees processes that load it, and "was not seen" is not "did nothing"), the subject replacing its own image, threads, and processes that leave the containment group (`setsid`/`setpgid` are now interposed and recorded as `.detached`).
- Trace contract v3: every record carries the pid of the process that performed the operation, read live rather than cached so a forked child cannot inherit its parent's identity. `posix_spawn` is recorded as `.spawn` instead of `.fork` — misclassification was harmless while both were refused and becomes a hole the moment one of them is not. Boundary records are written after the call succeeds (a failed fork is no longer a boundary), except `exec` and `vfork`, which have no "after" to record from and err toward refusal. Two recording runs now produce traces that are identical after normalising pids to order of first appearance, and the acceptance suite compares exactly that.
- When a boundary was tolerated, the state is snapshotted twice after each contained run and any disagreement is `state_not_quiescent`: a reparented grandchild is nobody's child to wait for, so quiescence is observed, never proven, and the report's new `processes` line says what was observed and that a FAIL's window is attributed to the subject only.
- The oracle refuses what tolerance must not admit through the raw side door: a `clone` carrying `CLONE_THREAD` (a thread past the pthread wrapper), an unshimmed child's `setsid`/`setpgid` (traced explicitly — `%process` does not include them), and a `PROT_WRITE|MAP_SHARED` mapping of a state file (a mutation with no later write syscall, from the subject or anyone). A child's read-only `open` is tolerated as the read it is, and every flag is read from its own syscall argument, never from the whole line — a file named `O_CREAT.bak` changes nothing.

### Fixed

- Interposing `vfork` killed the target. The replacement was an ordinary function, and its stack frame spans `vfork`'s double return on the stack the child shares with the suspended parent: the child clobbered the frame on its way through, and the parent resumed through the corrupted saved registers into the child's branch — exiting 127 with no output, no signal, and nothing recorded. sideeye then reported `UNKNOWN recording_run_failed`, blaming the target for a death it had caused. Measured with the control that placed the fault: the target died identically under a shim that was loaded but *inactive*, so the recording path was never the cause. The wrapper now records the boundary and reaches the real `vfork` through a guaranteed tail call (`@call(.always_tail)`, a compile error on any backend that cannot honour it), so no frame exists at the moment of the call; the interposition stays, because dropping it would leave a `vfork` child invisible on the platform that has no oracle. Present in v0.1.0.
- Anything the target spawned outlived the run. The engine waited for the direct child only, so a grandchild kept writing into the state directory while the engine was snapshotting it, restoring it for the next world, or running the checker — the verdict described whatever happened to be on disk when the engine looked. Every child now runs in its own process group, and **descendants still in that group** are signalled once the direct child has exited. Reported as a fix rather than a feature because the hazard was present in v0.1.0, hidden only by the fact that targets which create processes are refused before any world is explored.

### Notes

- Confining the group is the strongest guarantee available here, and it is not a proof that nothing remains. A grandchild is reparented away when its parent dies, so `waitpid` reporting no children says nothing about it; and a descendant that calls `setsid` or `setpgid` leaves the group entirely, which nothing yet detects. Establishing that the state directory has actually stopped moving is a separate step, and it will be an observation rather than a proof.
- Under an oracle the recording run is not timing-equivalent to an explored world: `strace -f` does not exit until its tracees do, so a stray child's work lands inside the measured window. Documented in `docs/adr/0002-boundary-events.md`.

## [0.1.0] - 2026-08-10

First release. It proves the assumption the whole tool rests on — that a process can be killed deterministically immediately before its k-th file operation, and that the resulting worlds can be judged — and refuses to answer where it cannot see.

### Added

- Crash-point exploration: a target is killed deterministically immediately before each of its file operations, and every resulting world is judged. Crash points are addressed logically ("after `unlink(key.json)`, before `rename(key.json.tmp)`") rather than by counter alone.
- Userspace interposition on Linux (`LD_PRELOAD`) and macOS (`DYLD_INSERT_LIBRARIES` with a `__DATA,__interpose` table). Both reach the same logical crash point for the same scenario.
- Built-in L0 atomicity invariant, requiring no configuration.
- L2 domain checkers via `--check`, run after restart in a fresh process, with the exit code as the verdict. A checker that cannot distinguish a corrupted state from a healthy one is refused before exploration begins.
- Completeness oracle on Linux: the recording run is compared against `strace`, normalised to the same operation classes the shim records. The report states how much was examined.
- Structural detectors that need no oracle — a missing shim marker, a state directory that changed while nothing was counted, and a contract version mismatch.
- Exit-code contract: 0 PASS, 1 FAIL, 2 UNKNOWN, 3 SETUP ERROR. UNKNOWN is never 0.
- `--allow-unverified`, for platforms where no oracle is available. PASS then carries `oracle: NOT VERIFIED` in the report; FAIL is unaffected.
- Text and JSON reports (`--json`) carrying the same content: verdict, crash point, logical window, explored count, what the oracle and checker established, and what was not tested. The report is written whole or not at all.
- An invariant that fails in the world that was never crashed is UNKNOWN, not FAIL. A checker that rejects the operation's normal output, or an operation broken on its own, is not a crash-consistency counterexample, and reporting one as "N of N crash worlds violated" would blame crashing for something that happens without it.
- Continuous integration across both operating systems and both architectures, asserting that the verdict and the crash point match, and executing the `reproduce` line the report prints.

### Notes

- Targets that leave the supported boundary — raw syscalls, static linking, a hardened runtime, `fork`/`exec`, threads, or operations outside the modelled set — are reported UNKNOWN. They are never reported as passing.
- PASS requires a completeness check. Without one, the run ends UNKNOWN unless `--allow-unverified` is given.
- Configuration is by command-line flags in this release. The `sideeye.toml` contract described in DESIGN §12 arrives in v0.2, along with L1 success markers.
- Reproduction is by re-running the operation with the environment the report prints. `sideeye replay <case>` needs case storage, which arrives with it in v0.2.
- `--operation` must exit 0 when it is not being killed. The crash points are read off that run, so a target that fails partway through is reported UNKNOWN rather than explored against a sequence it never performs.
- The report schema is experimental and may change in any release before 1.0, along with the Define contract and the exit codes.
- Defects found and fixed before this release are not listed here — no user saw them. They are in [BUILDLOG.md](BUILDLOG.md), including the ones that took several attempts.
