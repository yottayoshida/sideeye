## [0.9.0] - 2026-08-15

The exec-boundary release: a subject that execve-replaces itself stays judged (trace contract v10), a restarted operation counter is a named refusal instead of a wrong-address verdict, the falsification gate's output carries its speaker on every line, and the front page's claims are trued against what actually stands. Saved v9 cases refuse honestly as a contract mismatch and must be re-recorded.

### Added

- Single-pid execve chains are judged (#123, trace contract v10, ADR 0018): the shim's exec wrappers carry the operation count across the image change (`SIDEEYE_SEQ_BASE`; subject-only, vfork-safe, never truncating the target's environment), the re-run init continues numbering, and `shim_ready` re-announces the base as its seq. The engine tolerates a subject exec only when that continuation evidence arrives; wrong base, a second exec inside the window, or end of trace refuses with the escape named (execl family and fexecve are not interposed, a static image loads no shim, a stripped environment carries nothing). Measured: the planted-bug toy is FOUND across a self-exec with the oracle agreeing on all 8 operations; fork+exec children stay refused precisely. pass advances past the exec refusal to the child refusal — its verdict needs the multi-process slice, and #123 stays open for it.
- A numbering-integrity refusal, `sequence_numbering_broken`: the subject's kill-point record count and its highest sequence number must agree, in the recording and in every world. A restarted counter after an unobserved exec is a duplicate number that `prefixHash` provably cannot see; measured live, an execl-based self-exec is caught by exactly this check, and with it disabled the same run produced a confident false PASS.

### Changed

- The oracle no longer refuses a second execve by the subject: whether the chain of observation survived the image change is the shim's evidence to give, and the engine holds it structurally — a second same-pid `shim_ready` with no exec record before it is itself an image change and refuses, as does a window that never closes; the oracle's completeness comparison additionally refuses when a post-exec in-scope operation escaped the shim. Raw threads, shared-fs clones, unshare and the child-touch witness are unchanged.
- Saved v9 cases refuse honestly as a contract mismatch and must be re-recorded; the four assisted cohort cases were (identical verdicts, fresh-container replays reproduced — `spike/assisted/REMEASURE.md`).
- The falsification gate's child output (the checker's message and the target's own stderr while the gate proves the checker can go red) is captured and re-emitted with a per-line `falsify: ` prefix (#134). By design that step produces exactly the output a real finding would, and an unlabeled gate line was once harvested from a transcript as world evidence; a line copied out of the gate segment now carries its speaker with it. World, recording and setup output are unchanged.
- The copy no longer promises the "smallest reproducible counterexample" (#93): what ships is the earliest failing crash point, saved as a replayable case, and the front page, DESIGN's overview and one-sentence definition, and the report schema's `earliest` description now say exactly that.
- The MCP docs state plainly that root confinement is not a sandbox (#96): `SIDEEYE_MCP_ROOT` confines which config may be named, never what its operation may do — README's MCP section and ADR 0010's consequences carry the sentence and the containment recommendation (a container or otherwise restricted workspace).
- The README's real-tool findings paragraph is trued against what stands: five tools with replay-confirmed counterexamples (the buku claim was withdrawn — the recorded evidence was the falsification gate's own output), four upstream reports (GNU Stow and calcurse filed 2026-08-15, awaiting a maintainer response), and the devtodo finding recorded in-repo, deliberately unreported upstream.

## [0.8.0] - 2026-08-15

The judge's-reach release: symlinks become first-class kill points (trace contract v9) and ownership/permission writes are recorded-only — together these took four blocked real-tool defines to verified, replay-confirmed counterexamples the same day (`spike/assisted/REMEASURE.md`). Saved v8 cases refuse honestly as a contract mismatch and must be re-recorded.

### Added

- `symlink`/`symlinkat` are first-class operations (#122, trace contract v9): recorded as kill points on the LINK PATH (the target string is content the subject chose — never resolved, never recorded), snapshotted as (kind, readlink-target), restored verbatim (a dangling link is restored dangling), and retargeted by the checker-falsification probe so link-farm checkers stay falsifiable. Saved v8 cases refuse honestly as a contract mismatch and must be re-recorded. Measured motivation: the #118 assisted cohort's stow run refused on `symlinkat`.
- Ownership/permission writes are recorded-only (#121, option b): the chown/chmod families change none of the judged state (names, bytes, link targets), so the oracle observes them, the verdict excludes them — from kill points, from `unsupported`, from the child-touch condition — and the report declares the exclusion per run in a new always-present `metadata_writes` field (text and JSON). Without an oracle the field says these writes are not observable at all; absence of a note is never absence of writes. Measured motivation: sqlite's journal fchown (buku) and devtodo's per-rewrite fchmodat each sent a whole #118 cohort target to UNKNOWN.

### Changed

- The built-in invariants judge each shared path by its (kind, content) pair on BOTH sides, including pairs whose kind changes between the clean runs (stow's unfold: fold symlink → real directory) — previously such pairs were silently skipped, which was invisible while the oracle refused every symlink-touching target and became an undisclosed hole the moment v9 removed that refusal. A world killed mid-swap matches neither identity and is a violation, the same rule the file world's delete-then-recreate window already lived under. L1 judges a post-only symlink by its target (its whole identity — the existence-only gap's rationale does not transfer to links). The `l0` report note now counts "path(s)", not "file(s)".

## [0.7.0] - 2026-08-13

The PASS-side soundness release: no descriptor number is exempt from observation (trace contract v8), and a target whose success convention is a non-zero exit status is declarable (`--expect-status`, case schema v2). Saved v7 cases refuse honestly as a contract mismatch and must be re-recorded.

### Added

- `--expect-status <n>` / `expected_status = "<n>"` (#3, ADR 0014): declare the exit status that means the operation completed, for targets with git-style status conventions — previously refused on every invocation with no way to opt out. One declared value governs every un-killed run of the operation (the recording run and the baseline world; a status mismatch names both the expected and the actual status, and a signal death is reported as such — it has no exit status to name), killed worlds still require the kill signal itself (`_exit(137)` is an exit, never a SIGKILL), preflight accepts the declaration and carries it in its graduation hint, and the report gains an always-present `expected_status` field so a PASS over a non-zero convention is machine-distinguishable. Saved cases freeze the declaration as case schema v2; v1 cases keep replaying (absent means 0).

### Changed

- Trace contract v8 (#4): no descriptor number is exempt from observation. The shim previously skipped fd 0/1/2 (and its own trace fd) unconditionally — a target that `dup2`'d a state file onto a standard descriptor wrote invisibly, measured as a false PASS on the oracle-less path (with the oracle, the second witness already refused). Every fd-addressed operation now resolves the descriptor's actual location, fd resolution is three-valued (a proven socket/pipe/device is out of scope; a path query that fails on a real file records `unresolved` and the run refuses; `st_nlink == 0` finally marks open-but-unlinked files on macOS), and saved v7 cases refuse honestly as a contract mismatch. (ADR 0013)
- The shim's trace descriptor defends its own identity: relocated at init above the range daemonize-style `close(3..255)` hygiene sweeps reach, and a target closing it is answered with one final `unresolved` record and silence, so the run refuses as `unresolvable_path`. Measured before the guard: the swept number was re-used by the target's own state file, which came back with the shim's binary trace records spliced between its bytes — the harness corrupting the data it judges.

### Fixed

- `--work` inside the state directory is refused before anything runs: with the descriptor exemptions gone, the engine's own stdout captures there would have been observed as the target's state operations. The vet runs before `--fresh-state`'s deletion (the first version emptied the state directory and then refused, destroying the caller's data on an invalid setup), cleans up the one directory its resolution creates, and treats a state directory of `/` as containing every `--work` (the hand-rolled prefix test it replaced did not).
- Anon-inode descriptors — eventfd, epoll, timerfd, io_uring, whose fstat type bits are zero by design — no longer send the run to `unresolvable_path` on close; every epoll-based target was unjudgeable. `O_PATH` symlink descriptors are likewise proven non-state; kqueue on macOS stats as a FIFO and was never affected.
- The `*at()` family's base-descriptor resolution had the same proof/failure conflation `noteFd` was reviewed for: a real directory whose path query failed was answered "not ours". Found by the same-class scan; same three-valued fix.
- `docs/report-schema.md` said "v7 today" over a v8 binary; the schema check now pins the doc's version words to `contract_version`, so this class of drift goes red in CI.

## [0.4.0] - 2026-08-12

The v0.4 milestone — dogfood: omamori — delivered: DESIGN §17's primary criterion evaluated honestly across omamori's full surface, and regression-case stability measured across a real fix. This release also ships the MCP adapter ahead of its milestone: v0.5's agent-facing surface landed on main before v0.4 was cut, so it rides here — the v0.5 milestone itself (the loop-closure test) remains open and will cut 0.5.0.

### Added

- Regression-case stability, measured across a real fix (`spike/dogfood-timew-replay.sh`): one saved timewarrior counterexample driven through four legs — FAIL with the case saved on the pinned upstream build (full 40-hex pin, enforced with `git rev-parse` after checkout), FAIL again on replay against the same build ("the case reproduced"), **PASS** across the fix patch rebuilt in a separate checkout under the same command name (explored 2, landing context intact — ADR 0009's paths-only-warn carrying a same-class rename reorder, exactly what it was written for), and a refusal (`case_no_longer_applies`, naming the operation-count mismatch) against a build whose recording differs. Judgments read the JSON reports with explicit checks, not `assert` — `assert` vanishes under PYTHONOPTIMIZE (#58 tracks the older suites).

- The omamori surface enumeration (`spike/dogfood-omamori-surface.sh`), closing v0.4's last self-admitted gap: every subcommand including nested arms, the argv0 shim mode and the hook entrypoints, cross-checked from the write-primitive side. Of the four unguarded writers, install/setup refuse at `symlinkat` and init at `fchmodat` (named trace-contract walls), and audit verify's high-water-mark bootstrap write explores fully and holds (PASS over 6 crash points — the first omamori surface explored to a verdict rather than met at a wall). The probes pin their outcomes, which is what caught the recipe's own wrapper exec masquerading as target structure; the one non-atomic write found — retention's in-place prune rewrite on the append path — is recorded in the buildlog as an open finding.

- `sideeye mcp` (ADR 0010): a stateless MCP 2026-07-28 stdio server, so a coding agent can drive sideeye through the standard tool surface. Two tools, both taking a path inside `SIDEEYE_MCP_ROOT` — `sideeye_explore_config {config_path}` and `sideeye_replay_case {case_path}` — never a raw command (the operation lives in the config, a trust boundary). The server self-execs the canonical binary (`/proc/self/exe` / `_NSGetExecutablePath`, not argv[0]), captures the child's stdout to a file so the MCP transport stays uncontaminated, and gives the child a minimal environment so a config's operation cannot read the server's credentials. `_meta` (protocol version + client capabilities) is validated on every method; an unsupported version returns `UnsupportedProtocolVersionError`. A crash-consistency PASS/FAIL is `isError:false`; every other outcome (SETUP_ERROR, every UNKNOWN) is `isError:true`, read from the report's `verdict` field. The shim, an optional oracle, and the work dir come from the environment (`SIDEEYE_MCP_SHIM` / `SIDEEYE_MCP_ORACLE` / `SIDEEYE_MCP_WORK`). Synchronous in v1 (a long explore blocks the loop; async/cancellation via the Tasks extension is future work).

### Fixed

- `sideeye mcp` no longer serves a stale verdict when two server processes share a work dir. The per-process artifact counter made both processes use `report-1.json`/`child-1.out`: the `O_EXCL` capture aborted the second child at 126, and the server then read the *previous* server's report back as the current call's verdict — measured answering about the wrong target. Stale artifact names are now unlinked before each child runs, and the fork stub's own exit codes (126/127) become tool errors instead of a report read. A new acceptance check pins the cross-server reuse case, and the MCP acceptance suite now runs in CI (it previously ran nowhere, and its env-isolation and self-exec checks had been satisfied by exactly these stale artifacts).

- `sideeye mcp` `isError` is now derived from the report's `verdict` field (PASS/FAIL are verdicts; everything else is actionable) instead of a fixed list of six `unknown_reason` substrings. Any reason outside the list — `no_shim_marker` was measured live — previously rode through as `isError:false`, which an agent reads as a settled verdict.

- `sideeye mcp` `server/discover` and `tools/list` responses now carry `resultType`, `ttlMs`, and `cacheScope` — both results extend `CacheableResult` in MCP 2026-07-28, whose `ttlMs`/`cacheScope` are required, so a schema-validating client would have rejected the handshake. Also tightened: the `jsonrpc` version tag is validated, `clientCapabilities` must be an object, a transport write failure exits instead of leaving a half-written line on fd 1, and `sideeye mcp` refuses extra arguments instead of silently ignoring them.

## [0.3.0] - 2026-08-12

The full Define contract: what a user writes is a `sideeye.toml`, a checker script, and nothing else — and every level of the contract ships with the refusal that keeps it honest. Measured on a fresh target the same day: watson is driven to a correct, named refusal by the file, one script and one environment variable.

### Added

- Case storage and `sideeye replay` (ADR 0009). A FAIL saves its counterexample to `<work>/cases/NNNNNN.json` — the resolved define, the crash point, and a landing context (operation count, a hash of the class sequence up to the crash point, the classes and paths around it) — and prints the ready-to-paste `sideeye replay` line in text and JSON. Replay is `explore` restricted to the case's crash point plus the baseline: every trust gate (oracle comparison, structural detectors, checker falsification, landing evidence, quiescence) still runs. When the recording no longer matches the landing context — the count, the class prefix, or the adjacent classes changed, or the case came from a different trace contract — the answer is UNKNOWN `case_no_longer_applies`, never a verdict about a shifted address; path differences only warn (pid-embedded temp names differ between runs while naming the same operation).

- The L1 success marker (ADR 0008): `marker` in `sideeye.toml`, or `--marker`. In worlds where the operation's own success claim reached stdout before the kill, the post-success invariant is enforced against the whole post snapshot — shared files must hold the new content, history files must have grown, created files must exist, deleted files must stay gone (`not_durable`). A marker the clean recording run cannot produce refuses as UNKNOWN `marker_never_observed` instead of leaving every L1 obligation silently vacuous; a crash world killed before the marker is simply a world where the conditional does not apply, and is still judged by L0 and the checker. Every operation run now captures the target's stdout to the work directory (it is evidence, and it no longer interleaves with the report); the `l1` line/field reports how many crash worlds observed the marker, and the `checker` line how many worlds it ran in. Post-only file contents are deliberately not judged (nondeterministic content would fail correct targets) and `not tested` names that gap.

- `sideeye.toml` (ADR 0007): the define surface — `[world] state`, `[define] setup / operation / check` — in the file form DESIGN §12 promised, via `--config`. The parser is a hand-written strict subset that refuses everything outside the contract with the offending line named: unknown sections and keys, bare values, duplicates, empty values, escape sequences. Keys join the schema only once the engine enforces them (`marker` refuses until L1 lands). The file owns the define surface only — operational flags (`--shim`, `--oracle`, `--work`, `--json`, `--allow-unverified`) stay flags and combine with it; the define-surface flags are mutually exclusive with it, never merged. Relative paths resolve against the toml's own directory; command argv[0] resolves only when it names a place (`./check.sh`), never a program name. Command strings keep the flags' split-on-spaces rule, now written down.

- A refusal names the operation it refused on. `oracle_missed_operation` and `oracle_saw_phantom` now carry the 1-based divergence index, the raw strace line the oracle holds at that position, and what the shim's account holds there — or that either account simply ends — in the text report and the JSON `message` identically. Previously the comparison computed the divergence index and threw it away on the way to a one-line refusal, leaving the reader to decode `trace-record.bin` by hand; two dogfood sessions paid that cost in full. No schema change, no trace-contract change (v7 stays). On allocation failure the bare refusal survives without the naming — the refusal is the point, the naming is the courtesy.

- The shim observes `remove(3)` (trace contract v7). libc implements remove as unlink — then rmdir on the directory errno — *internally*, behind the PLT, so a target that removes state through it was invisible to the shim while the oracle saw every syscall: on Linux such a run refused honestly (`oracle_missed_operation`), but on macOS — which has no oracle — a mixed-visibility target keeps `mutation_count != 0` and leaves `state_changed_without_ops` silent, which is a PASS hole, not an ergonomic gap. The wrapper reimplements the documented two-step through the shim's own recorded unlink/rmdir wrappers, so every attempt is recorded before it runs and the account matches strace attempt for attempt: a failed remove of a never-created path is an address on both sides, and a directory shows glibc's failed unlink probe before the rmdir lands (Apple's BSD libc falls through on `EPERM` instead of `EISDIR`; each platform keeps its own libc's behaviour, warts included). Found by timewarrior, whose AtomicFile cleanup removes every registered temp name at exit, created or not. **Contract v7**: a target that removes state via remove gains crash-point addresses a v6 trace does not have — the same class of meaning change that bumped v4 and v5.

- `spike/dogfood-timew.sh`: the fifth real target, and the first counterexample on a real target that is not a precision artifact. One `timew track` commits three files by consecutive renames — month data, then `undo.data`, then `tags.data` — so every file is individually atomic and L0 alone passes 20/20 worlds; the bug is not in any file but between them. A checker stating only timewarrior's documented undo contract (undo removes exactly the interval timew's own export names as most recent) fails 2 of 20 worlds. Killed between the first and second rename, `timew undo` reports success and deletes an interval committed long before the crash, keeping the one whose commit crashed. Killed before the third, `timew undo` exits 255 ("Trying to decrement non-existent tag") and stays unusable until `tags.data` is repaired by hand — it undoes nothing, atomically, which is the good half. Both replayed end-to-end from the reproduce line. The falsification probe passes bare: `timew export` rejects a corrupted data file loudly (exit 255), the opposite of todoman's lenient reader.

- The oracle decides scope by resolving each syscall's real path arguments instead of scanning the whole line for a state-directory string (ADR 0006, trace contract v6). A relative path resolves against its `dirfd` annotation or the tracked working directory (updated from the subject's own `chdir`/`fchdir`), and one that cannot be placed is refused rather than dropped — closing a fail-open where a target that changed directory and spelled its paths relative slipped past the scope test entirely. The same change removes the matching false positive: a state-directory string sitting in a write buffer no longer scopes an fd write in. Two-path operations are in scope when either endpoint is inside the state directory, on both the oracle and the shim (which had judged only the first path, dropping an `outside → state` rename). `link`/`linkat` are now first-class kill points (`OpClass.link`); `linkat(AT_EMPTY_PATH)` and `clone(CLONE_FS)` are refused, and the oracle now honours the alternate state-directory spelling. Measured: git commit reaches account agreement (33 operations, 34 worlds) and a full verdict for the first time — the FAIL it reports is `COMMIT_EDITMSG`, git's editor scratch file, which `git fsck` accepts in every crash world, so git's real integrity is intact and the complaint is an L0 precision limit on a non-durable file. taskwarrior (PASS 12/12) and omamori (PASS 143/143) are unchanged. **Contract v6**: a v5 shim under a v6 engine refuses, because it records no link where a link happened.

- The shim observes stdio streams at flush granularity (ADR 0005, trace contract v5): a write-capable `fopen`/`fopen64` is an `.open`, a flush with pending bytes is a `.write` — at `fflush`/`fflush_unlocked`, at `fclose`, at `freopen`'s [write, close, open] triple, and at the seek family (`fseek`/`fseeko`/`rewind`/`fsetpos`), because libc flushes a dirty stream as a side effect of repositioning it (measured as the only thing standing between taskwarrior and a verdict). Recording happens before the call, so a kill lands before the flush and the crash world loses the unflushed buffer — what a real crash loses. What bypasses the flush path (a large `fwrite` going direct, overflow flushes inside `fprintf`, `fflush(NULL)`, `freopen(NULL, …)`'s reopen, exit-time cleanup of never-closed streams) stays unrecorded and, under an oracle, refuses as `oracle_missed_operation` exactly as before — the unjudgeable class just became much smaller. On macOS (no oracle) the same residue falls inside `--allow-unverified`'s already-declared weaker claim, while stdio visibility goes from zero to everything inside the boundary. Measured on the real targets that motivated #30: taskwarrior reaches **PASS 12/12 worlds** (and passes its own `task list` as an L2 checker in every crash world, after the falsification probe rejected a corrupted state); git's `COMMIT_EDITMSG` no longer splits the accounts and its run now stops one wall later (#31, relative-path oracle scope); omamori is unchanged at PASS 143/143. **Contract v5**: on Linux every affected run was UNKNOWN under v4, but a macOS `--allow-unverified` verdict over a stdio-mixed target could carry a reproduce line whose `k` counts different operations under v5.

- L0 carries a second per-file form, chosen from the snapshots alone: a file whose post-operation content strictly extends its non-empty pre-operation content — the shape of logs, journals and audit chains, whose appended bytes may legitimately differ between runs — is judged by **history preservation** (ADR 0004): after the crash the file must still begin with everything it held before the operation, with a new violation (`rewritten`) when it does not. The appended tail is deliberately not judged; whether a torn tail is acceptable is the target's recovery semantics and belongs to an L2 checker. Every report says which files were judged by which form (a new `l0` note in text and JSON — an addition to the experimental report schema, not a trace-contract change; the contract stays v4), and `not tested` grows "appended tails" whenever the form is in play. The relaxation is exactly as wide as the shape: a non-reproducible *rewrite* still ends in `UNKNOWN baseline_violates_invariant`, pinned by its own acceptance case.
- `spike/dogfood-omamori.sh`: the first real target's exploration, reproducible. Measured with it: the run that was structurally UNKNOWN in v0.2.0 now reaches **PASS 143/143** with `audit.jsonl` named under the history form — and with `--check "omamori audit verify"`, the target's own verifier judges every crash world, including the ~130 that hold a torn audit line (it skips the torn tail by design and accepts), after the falsification probe confirmed it rejects a corrupted state.

### Changed

- Crash-point addressing and the completeness comparison now cover **operations that can change state** (ADR 0003, trace contract v4). A write-incapable open — access mode `O_RDONLY` with neither `O_CREAT` nor `O_TRUNC` — mutates nothing, so the world killed immediately before it is byte-identical to the world killed at the next address; it is no longer observed, on either side of the comparison, under one predicate (`O_RDONLY|O_CREAT` stays addressable — creation can change the tree — though a target whose *only* state change is creating files via open is still refused by `state_changed_without_ops`, a pre-existing and deliberate strictness of that detector). `close` leaves the comparison but stays in the trace: the oracle sees descriptors the shim never saw born, and pairing closes across the views has no honest fixpoint. The oracle-side predicate is fail-closed — numeric or unparseable flags are counted as before, so a parse failure ends in UNKNOWN, never PASS. **`SIDEEYE_KILL_AT=k` counts state-changing operations from v4 on**: a `reproduce` line printed by v0.2.0 may name a different operation under a v4 shim, and a v3 shim under a v4 engine refuses loudly as `contract_version_mismatch`.
- Measured on the target that motivated the change: the two accounts now agree on 142 operations (previously `oracle_missed_operation` on a rustix-issued raw read-only open), all 143 worlds explore with every kill landing, and the verdict is `UNKNOWN baseline_violates_invariant` — correct, because omamori's audit line carries a timestamp and an HMAC chain, so the operation is not byte-reproducible and nothing found in a crash world could be attributed to crashing. The next wall is operation non-determinism versus L0's byte comparison, filed as its own issue.

## [0.2.0] - 2026-08-11

Process boundaries, judged by what the other processes did. This release was not on the roadmap: v0.2 was promised as the full Define contract (`sideeye.toml`, L1 markers, case storage and `replay`), and that scope moves to v0.3 unchanged. What forced the queue-jump was pointing v0.1.0 at its first real target — the run ended at a categorical refusal (`child_process_detected`) for a shape every shim, wrapper and launcher shares, and one of the fixes below removes a v0.1.0 defect that killed the very targets it observed.

### Added

- Process boundaries are now judged by what the other processes did, not by their existence. A target that forks or spawns helpers — the shim/wrapper/launcher shape that ended the first real-world run — is explorable when an oracle is present and no process other than the subject touched the state directory. The rule and the numbering are the same condition: a child that stays out of the state directory consumes no crash-point addresses (ADR 0002). Refusals that remain, each with its own detector: a child that touches the state directory (`child_touched_state_dir`, caught independently by the shim for children that load it and by the oracle for children that do not), any boundary without an oracle (`boundary_without_oracle` — the shim only sees processes that load it, and "was not seen" is not "did nothing"), the subject replacing its own image, threads, and processes that leave the containment group (`setsid`/`setpgid` are now interposed and recorded as `.detached`).
- Trace contract v3: every record carries the pid of the process that performed the operation, read live rather than cached so a forked child cannot inherit its parent's identity. `posix_spawn` is recorded as `.spawn` instead of `.fork` — misclassification was harmless while both were refused and becomes a hole the moment one of them is not. Boundary records are written after the call succeeds (a failed fork is no longer a boundary), except `exec` and `vfork`, which have no "after" to record from and err toward refusal. Two recording runs now produce traces that are identical after normalising pids to order of first appearance, and the acceptance suite compares exactly that.
- When a boundary was tolerated, the state is snapshotted twice after each contained run and any disagreement is `state_not_quiescent`: a reparented grandchild is nobody's child to wait for, so quiescence is observed, never proven, and the report's new `processes` line says what was observed and that a FAIL's window is attributed to the subject only.
- The oracle refuses what tolerance must not admit through the raw side door: a `clone` carrying `CLONE_THREAD` (a thread past the pthread wrapper), an unshimmed child's `setsid`/`setpgid` (traced explicitly — `%process` does not include them), and a `PROT_WRITE|MAP_SHARED` mapping of a state file (a mutation with no later write syscall, from the subject or anyone). A child's read-only `open` is tolerated as the read it is, and every flag is read from its own syscall argument, never from the whole line — a file named `O_CREAT.bak` changes nothing.

### Fixed

- Interposing `vfork` killed the target. The replacement was an ordinary function, and its stack frame spans `vfork`'s double return on the stack the child shares with the suspended parent: the child clobbered the frame on its way through, and the parent resumed through the corrupted saved registers into the child's branch — exiting 127 with no output, no signal, and nothing recorded. sideeye then reported `UNKNOWN recording_run_failed`, blaming the target for a death it had caused. Measured with the control that placed the fault: the target died identically under a shim that was loaded but *inactive*, so the recording path was never the cause. The wrapper now records the boundary and reaches the real `vfork` through a guaranteed tail call (`@call(.always_tail)`, a compile error on any backend that cannot honour it), so no frame exists at the moment of the call; the interposition stays, because dropping it would leave a `vfork` child invisible on the platform that has no oracle. Present in v0.1.0.
- Anything the target spawned outlived the run. The engine waited for the direct child only, so a grandchild kept writing into the state directory while the engine was snapshotting it, restoring it for the next world, or running the checker — the verdict described whatever happened to be on disk when the engine looked. Every child now runs in its own process group, and **descendants still in that group** are signalled once the direct child has exited. Reported as a fix rather than a feature because the hazard was present in v0.1.0, hidden only by the fact that targets which create processes are refused before any world is explored.

### Notes

- Confining the group is the strongest guarantee available here, and it is not a proof that nothing remains. A grandchild is reparented away when its parent dies, so `waitpid` reporting no children says nothing about it; and a descendant that calls `setsid` or `setpgid` leaves the group entirely, which nothing yet detects. Establishing that the state directory has actually stopped moving is a separate step, and it will be an observation rather than a proof.
- Under an oracle the recording run is not timing-equivalent to an explored world: `strace -f` does not exit until its tracees do, so a stray child's work lands inside the measured window. Documented in `docs/adr/0002-boundary-events.md`.

## [0.1.0] - 2026-08-10

First release. It proves the assumption the whole tool rests on — that a process can be killed deterministically immediately before its k-th file operation, and that the resulting worlds can be judged — and refuses to answer where it cannot see.

### Added

- Crash-point exploration: a target is killed deterministically immediately before each of its file operations, and every resulting world is judged. Crash points are addressed logically ("after `unlink(key.json)`, before `rename(key.json.tmp)`") rather than by counter alone.
- Userspace interposition on Linux (`LD_PRELOAD`) and macOS (`DYLD_INSERT_LIBRARIES` with a `__DATA,__interpose` table). Both reach the same logical crash point for the same scenario.
- Built-in L0 atomicity invariant, requiring no configuration.
- L2 domain checkers via `--check`, run after restart in a fresh process, with the exit code as the verdict. A checker that cannot distinguish a corrupted state from a healthy one is refused before exploration begins.
- Completeness oracle on Linux: the recording run is compared against `strace`, normalised to the same operation classes the shim records. The report states how much was examined.
- Structural detectors that need no oracle — a missing shim marker, a state directory that changed while nothing was counted, and a contract version mismatch.
- Exit-code contract: 0 PASS, 1 FAIL, 2 UNKNOWN, 3 SETUP ERROR. UNKNOWN is never 0.
- `--allow-unverified`, for platforms where no oracle is available. PASS then carries `oracle: NOT VERIFIED` in the report; FAIL is unaffected.
- Text and JSON reports (`--json`) carrying the same content: verdict, crash point, logical window, explored count, what the oracle and checker established, and what was not tested. The report is written whole or not at all.
- An invariant that fails in the world that was never crashed is UNKNOWN, not FAIL. A checker that rejects the operation's normal output, or an operation broken on its own, is not a crash-consistency counterexample, and reporting one as "N of N crash worlds violated" would blame crashing for something that happens without it.
- Continuous integration across both operating systems and both architectures, asserting that the verdict and the crash point match, and executing the `reproduce` line the report prints.

### Notes

- Targets that leave the supported boundary — raw syscalls, static linking, a hardened runtime, `fork`/`exec`, threads, or operations outside the modelled set — are reported UNKNOWN. They are never reported as passing.
- PASS requires a completeness check. Without one, the run ends UNKNOWN unless `--allow-unverified` is given.
- Configuration is by command-line flags in this release. The `sideeye.toml` contract described in DESIGN §12 arrives in v0.2, along with L1 success markers.
- Reproduction is by re-running the operation with the environment the report prints. `sideeye replay <case>` needs case storage, which arrives with it in v0.2.
- `--operation` must exit 0 when it is not being killed. The crash points are read off that run, so a target that fails partway through is reported UNKNOWN rather than explored against a sequence it never performs.
- The report schema is experimental and may change in any release before 1.0, along with the Define contract and the exit codes.
- Defects found and fixed before this release are not listed here — no user saw them. They are in [BUILDLOG.md](BUILDLOG.md), including the ones that took several attempts.
