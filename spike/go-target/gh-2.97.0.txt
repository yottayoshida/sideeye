Measured 2026-08-29 for #390, against the working tree of the branch that adds the
measured refusal detail (#391). Recorded because docs/target-classes.md's Go clause
labelled itself a prediction: "that is a statement about linking, not a measured Go run".

The answer differs between the two artifacts: the same tool version, obtained two ways,
meets two different walls. Which axis does it is not measured here — OS, toolchain,
CGO_ENABLED, imports, buildmode and packaging all differ between them at once — so what
this records is that the language alone does not decide the wall.

== What this does and does not establish ==

It establishes what these two artifacts of this version do on these two hosts. It is not
a statement about Go: linkage there moves with the OS, CGO_ENABLED, the imports actually
reached, buildmode and whether an external linker ran, so a differently built gh — or any
other Go tool — has to be measured rather than inferred from this row.

What it does show is that "Go tools are refused for static linking" is wrong as a class
claim, and wrong in a way that costs a reader a real run: on macOS a Homebrew-built Go
tool gets one wall further, and the wall it meets has a different fix path.
