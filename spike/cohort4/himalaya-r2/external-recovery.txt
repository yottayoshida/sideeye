==============================================================
The answer the freeze asked for, and its limits.
==============================================================
   RECOVERY PATHS THAT EXIST:
     1. The source message survives, so the copy can be repeated (R4,
        R7). This restores the intended message. It does not remove
        the empty one: the folder afterwards holds both, and the tool
        lists both as messages.
     2. The empty message can be deleted by hand, once the user knows
        it is there and the account names a trash mailbox (R5).
   
   CONDITIONS UNDER WHICH THEY DO NOT APPLY:
     Both paths require the user to notice. Nothing offers to.
     The tool has no command that inspects stored mail (R1, 2 matches
     in 216 and neither reads a mailbox), its one check-shaped command
     reports the account OK over the damaged store (R2), and an
     independent maildir reader enumerates the empty file as an
     ordinary message as well (R6). In the listing the only difference
     is blank columns and 0 B.
   
   THE SYNCHRONIZED SIDE, WHICH THE FREEZE ASKED ABOUT SPECIFICALLY:
     It cannot help, and not only in the maildir-only configuration
     the freeze names. The operation copies between two folders inside
     one local root and makes no network syscall at all (R3, 0 against
     a positive control of 2), and this version of the tool has no
     sync command in any of its 216 (R1). The message being created in
     the target folder has therefore never existed anywhere else at
     the moment it is destroyed. A remote side cannot restore content
     it has never seen.
   
   NOT MEASURED, AND STATED RATHER THAN IMPLIED:
     Whether an EXTERNAL syncer (isync, offlineimap) managing this
     maildir would upload the empty message to the server as a new
     message, which is the shape the freeze calls the strongest form:
     the external recovery path itself carrying the damage outward.
     Measuring it needs a second tool and a server, neither of which
     is in this image. It is a question about making things worse,
     not about recovery, so the recovery question above is answered
     without it.
