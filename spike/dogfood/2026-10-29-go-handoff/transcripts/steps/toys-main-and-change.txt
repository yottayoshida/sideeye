== mine supervised [none] rc=2
UNKNOWN  multiple_threads_detected
next        Two threads of one process wrote the judged directory, and under --observe supervised no join is recorded, nor which thread a creation made, so nothing orders their writes. In every mode, threads are judged only where a creation or a join orders their writes, and these two writes are not. An order that only a lock, a queue or a wake sets does not count. A tool's own switch for running its file calls on one thread can move it past this — UV_THREADPOOL_SIZE=1 for Node, GOMAXPROCS=1 for Go (it moved some Go tools past this; in others GOMAXPROCS=1 does not stop Go's runtime moving one run of writes from one OS thread to another, which this mode reads as two threads): set it in the environment Sideeye runs in and declare it in the define's apparatus (env:GOMAXPROCS=1, for example); https://github.com/yottayoshida/sideeye/blob/v1.16.0/docs/apparatus.md#a-tools-own-switch-for-one-thread lists the switches measured and the targets each did not move.
