sideeye dogfood の候補集め、2 回目の結果。fresh で、星 1,000 以上・2026-04-07 以降に push・archive されていない・issue が有効、の 4 つを満たしたのは 42 件。そのうち規則 5 が中程度以上で、書き換えるコマンドを確かめられた 31 件を表にした。残る 11 件は規則 5 が弱いか懸念が大きいので、最後に名前だけ挙げる。ファイルは作っておらず、使ったのは fresh.sh・`gh api repos/`・読み取りのシェル・Web 検索だけ（`gh api search` は使っていない）。

【要判断】
- chia と kubo: コマンドが書き換えるのは YAML・JSON・鍵のファイルだが、道具全体の主な保管先は組み込み DB（chia はチェーンとウォレットが SQLite、kubo は datastore が leveldb）。規則 6・7 で入れるか決めてほしい。
- llama.cpp の gguf-set-metadata: numpy の memmap で書き換えるので、書き込みが write 呼び出しとして出てこない恐れがある。sideeye で見えるかどうか。
- hass（Home Assistant）: 道具の本体はサーバー（規則 4）。CLI は付属のスクリプト。
- fabric が SEEN と出たのは「fabricated」という語に当たっただけ。持ち主 danielmiessler の名前でも照合して fresh だった。

指定された分野はほぼ掘り尽くされていた。plain-text accounting・連絡先と予定表・RSS・ドットファイル・ブックマーク・OTP・KeePass・XMP・BibTeX・version manager は、主な道具がすべて SEEN だった（hledger、khard、khal、newsboat、chezmoi、yadm、keepassxc、papis、jrnl、pyenv、mise、direnv、dotenvx など）。crontab・at、翻訳メモリ、Jupyter 以外のノートブック、API クライアントのコレクションは、条件を満たす CLI が見つからなかった（ネットワークが要るか、新しいファイルを作るだけ）。ATAC だけはオフラインでコレクションを書き換えられた。
