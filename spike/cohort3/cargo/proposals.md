# Cohort-3 define: cargo (target 1)

Target: cargo 1.98.0 (the image's pinned current stable). Probe:
conditions 1–6 machine-green with condition 7's ambient evidence
printed, `../probes/cargo.txt` — byte-deterministic state root,
fail-closed closure over the state root plus the ambient `CARGO_HOME`,
`Cargo.lock` measured to update on `add`. Scout sources: the cargo book's
manifest-vs-lockfile page and the cargo-add manual (read 2026-08-22),
plus the probe transcript. Assisted provenance, per the cohort protocol.

## Why this target, this operation

`cargo add` is the sweet spot the cohort exists to measure: a plain-file
manifest edited by a tool with no transaction machinery between the
write and the disk, on the most-used Rust workflow there is. The probe's
mutating set inside the state root is three paths — `Cargo.toml`, its
rename-source temp file, and `Cargo.lock` — and that temp file is
itself evidence: the manifest write is atomic, the lock write is not
(the torn-lock section below).

## The property (P1, chosen)

**Kill `cargo add --offline --path <dep>` anywhere; the project must
survive to cargo's own reader.** Concretely, after the crash:

- **leg V**: `cargo metadata --offline` parses and resolves the crashed
  project — a torn manifest that no cargo command can read again is the
  failure this define exists to catch;
- **leg T**: the dependency set is old-or-new, never a third thing — the
  manifest names depcrate zero times (old) or exactly once (new), and
  metadata's resolution agrees with whichever it is;
- **leg C**: the source file is conserved byte-for-byte.

`Cargo.lock` is deliberately not asserted in lockstep with the manifest:
the cargo book says the lockfile "is maintained by Cargo and should not
be manually edited" (read 2026-08-22) — derived state whose re-sync is
cargo's own job, which leg V exercises by running cargo's reader. L0
still judges the lock's bytes (old-or-new per file); the checker judges
what the docs actually promise, not a simultaneity they never state.

## The torn-lock reading, frozen before the explore (owner ruling, 2026-08-22)

The probe's strace shows the likeliest crash shape, so its reading is
decided here, before any world exists. Four measured facts (the raw
probe strace and an engine-free container drill, 2026-08-22):

1. cargo writes `Cargo.toml` through a temp file and `renameat` —
   atomic — but rewrites `Cargo.lock` **in place**
   (`openat(O_RDWR|O_CREAT)`, no temp, no rename): the same crash, the
   same directory, one file protected and the other not.
2. A lockfile torn mid-entry makes `cargo metadata --offline` fail with
   `error: failed to parse lock file` (rc 101), no recovery hint.
3. A lockfile that is **absent** is silently regenerated by the same
   command (rc 0) — cargo's automatic maintenance handles "no lock"; a
   torn lock is strictly worse than no lock.
4. The drill `V-red-torn-lock` pins fact 2 in this define's own
   checker (`checker-drills.txt`).

**The ruling: no recovery leg.** The checker requires that cargo's own
reader reopen the project without manual intervention. Running the
reader IS letting cargo's documented, automatic maintenance run — it
regenerates an absent lock by itself, and a torn lock is exactly the
state where that maintenance refuses to engage. A world where every
subsequent cargo command fails until a human deletes a file cargo told
them never to edit is the failure this property names, so a torn-lock
world is **checker-red — a criterion-1 candidate shape**, not a
precision-limit observation. Whether any resulting candidate is
claimed or reported stays behind the standing gates (novelty search,
per-report owner approval, author confirmation); this ruling decides
the reading, not the report. The rejected alternative — a recovery leg
that deletes and regenerates the derived file — would encode a manual
step no cargo document prescribes, and was declined by the owner with
the measurements above on the table.

## Where the crash lands

Every kill point inside the add: the manifest rewrite, the lockfile
rewrite, and whatever ordering cargo puts between them.

## Rejected shapes

- *Assert manifest+lock simultaneity* — not a documented promise;
  asserting it manufactures FAILs out of cargo's own maintenance model.
- *Registry dependencies instead of a path fixture* — brings the network
  and the registry cache into the judged surface for no extra crash
  semantics; the path fixture keeps resolution closed (probed).

## Disclosed forecast (the probe's, carried here)

Every fresh `add` vforks one child, `rustc -vV`, which spawns one
internal thread; the shim observes threads and the engine may refuse.
That refusal, if it comes, is this define's recorded outcome — walls are
measured through the same discipline as finds. The documented `RUSTC`
override (a version-printing stand-in) is a possible apparatus for a
revision, **owner-gated, not assumed**.

## Stock reproduction

Any finding must reproduce against stock cargo with no apparatus beyond
strace fault injection before it is claimed or reported — the cohort
rule, unchanged.
